
# Version Control Systems: Understanding Git and GitHub

## Introduction to Version Control
Version control is used to help track the changes made when working on  a project overtime. It helps with all sorts of changes like when, what and why changes were made. This is beneficial as we can see all the updates and improvements to our projects as we progress. With no version control, its hard to work on files we want to see old changes too, and the progress made. I used Git to save progress, instead of doing all of it at once. 

## How Version Control Tracks Changes: 
Git tracks changes by saving the amount of commits, a commit in my own terms is like a checkpoint a part of the greater project. It explains the reasoning fro any changes, and has a unique ID which I find very helpful to know which version of the project I'm on. 

## Three collaboration benefits with Examples:

### Parallel work through branching:
Branch gives developers the ability to work on any aspect of the parts of the project they wish to work on without affecting the main branch. For example a person can work on the about page while another member can work on styling, the main ranch stays stable. In this assignment I used a feature branch and created a page about individuality. After it was pushed to GitHUb and merged with the pull request. 

### Code Review Through Pull Requests 
Pull requests allow me to check all the changes made even before added to the main project, like when a new page is created, we can review the file and approve before it merges, which helps find mistakes if any before it reaches the main branch.  Pull requests also show all the commits and changes files all in one area, which makes collaboration very organized because I don't have to send all the files manually 

### Safer Recovery When Problems Happen 
Git makes it very easy to recover from mistakes alike when a CSS change has broken the website layout, Git will show all of what changes and how will help restore it to normal working. Developers can compare both old and new versions to better identify the issue, which makes experimenting safe as project history will be saved. 

## Git’s Backup and Recovery Mechanisms 
All project history is stored in .git folder, which keeps all commits, branches, and information of the repository. A full copy can exist on more than one PC which is great for storage. Online backup is also a possibility when pushing to Github , so if one PC has an issue, the project can still be cloned. In Git recovery commands like fit reset and git revert help find older commits, make changes and check repo issues.

## Difference Between Git and GitHub 
Git is a version control tool running on the PC, where Github is an online platform for hosting its repositories. Git can be offline, where Github requires internet to be used usually,Git tracks commit and branches where github adds features like pull requests, and lastly it is got managing the history and github is for sharing collabing the history
